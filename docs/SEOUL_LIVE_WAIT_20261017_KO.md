# 서울 실시간 대기 구현 기록 — 2026-10-17

릴리스 ID: `seoul-live-wait-20261017-r3`.

## 구현 결과

러너의 남은 거리와 최신 GPS 페이스로 횡단 도착 시각을 구하고, 앞 횡단의 대기·보행 시간을 다음 도착에 누적한다. 기존 고정 계획 확인 외에, 실시간 보행 상태와 잔여값으로 한 번의 녹색 구간을 계산하는 경로를 추가했다. 단기 계산에는 전체 주기나 epoch를 만들 필요가 없다.

현재 녹색은 잔여시간 안에 보행 횡단과 여유 시간을 마칠 수 있는 도착에만 대기 0초를 준다. 현재 적색은 해당 잔여값이 다음 보행 녹색까지임을 검증하고, 그 녹색의 최소 지속시간을 확인해야 대기를 계산한다. 점멸·불명·결측·초과 범위는 `null`이다. 앞 횡단의 예측이 알려져도 이후 횡단이 미확인이면 경로 총대기는 `null`로 남긴다.

원천 관측은 최대 10초, 한 번의 예측 구간은 최대 300초다. 원천 시각에서 잔여값을 계산하므로 HTTP 수신 지연만큼 카운트다운을 다시 늘리지 않는다. 화면을 그대로 두어도 관측 만료 시 대기 합계를 지운다. 새 주기로 임의 반복하지 않는다. 기본 1초 불확실성 여유, 1.2m/s 보행 속도, 3초 횡단 여유는 시험 가정이며 현장 검증 결과가 아니다.

실행 중 응답 후 5초에 갱신한다. 최신 페이스·진행 거리를 사용하며 TMAP 경로를 매번 다시 받지 않는다. 일시정지·숨김 화면에서 폴링을 중단한다. API가 준 재시도 시각을 화면 복귀 후에도 지킨다. 429 후에는 최소 60초 또는 더 긴 `Retry-After`만큼 조회하지 않는다. 같은 서버 프로세스에서 동시 호출·짧은 반복 조회를 공유한다. 이 상태는 여러 서버 인스턴스 사이의 전역 할당량 제어는 아니다.

## 재호출 제한과 공공데이터 키 재점검

2026-10-17 재점검에서 기존 현시 API의 429 본문에 `code=V2X_REPEAT_CALL_LIMIT`, `api=v2xSignalPhaseInformation`, `limitSeconds=300`, `retryAfterSeconds=232`가 왔다. HTTP `Retry-After` 헤더는 없었다. 일 한도 소진으로 단정하지 않는다. 서버는 본문의 상대 재시도 시간도 읽고, 헤더와 본문 중 더 긴 시간을 지킨다. 이 명시적 API별 제한은 다른 교차로에도 적용하지만 현재 전용 API를 막지 않는다. 범위가 불명확한 한도는 기존처럼 계정 전체에 적용한다. 시간대 없는 `nextCallAvailableAt`는 UTC로 추측하지 않는다. 진단 스크립트도 현시 목록을 재사용해 같은 API를 연속 재호출하지 않는다.

공공데이터포털의 두 서비스는 T-DATA와 별도 인증이다. 제공받은 화면은 승인 및 활용기간 `2026-09-06 ~ 2028-09-06`을 표시한다. [행안부·한국지역정보개발원 공식 페이지](https://www.data.go.kr/data/15157604/openapi.do)의 내장 Swagger에서 `B551982/rti/crsrd_map_info`, `B551982/rti/tl_drct_info`와 서울 코드 `stdgCd=1100000000`을 확인했다. [경찰청 공식 요청 표](https://www.data.go.kr/data/15056721/openapi.do)는 `1320000/CrossRoadInfoService/getCrossRoadInfoList`, `ServiceKey`, `srchCTid=L01`을 명시한다.

공공데이터 키는 서버 환경변수 `DATA_GO_KR_SERVICE_KEY`로만 읽는다. Encoding/Decoding 양식을 한 번 정규화한 뒤 쿼리 인코딩한다. `/api/signals/national?service=current`, `service=map`, `service=police-crossroad`로 각각 실제 공식 경로를 조회한다. 진단 결과는 같은 프로세스에서 60초 공유하고, 429 및 게이트웨이 22·23 코드는 재시도 제한을 적용한다. 임의 URL·오퍼레이션은 받지 않으며 원천 오류 본문과 인증키는 반환하지 않는다.

개발 실행 환경의 실제 응답은 세 경로 모두 HTTP 400, `returnReasonCode=10` 파라미터 오류였다. 인증키를 빼도 같은 오류가 나왔다. 따라서 이 오류를 키 미등록·만료라고 단정하지 않는다.

2026-10-17 09:37 KST 운영 서버 점검에서는 RTI 두 경로 모두 HTTP 200이었다. 서울 교차로 목록 `totalCount=2779`, 신호 상태·잔여시간 목록 `totalCount=1`, 반환 교차로 `crsrdId=2691`, `totDt=20261017093603`을 확인했다. 동·서 보행 상태는 `stop-And-Remain`, 잔여 원시값은 `90`이었다. 같은 데이터 키로 운영 서버의 정상 수신을 확인했으므로 개발 환경의 400을 인증키 불량으로 판단하지 않는다. 이 한 건으로 서울 전역의 최신 신호 제공을 주장하지 않는다.

경찰청은 최초 운영 호출에서 HTTP 200이었지만 JSON 해석에 실패했다. JSON 외 공식 지원 형식인 XML도 처리하고, 숫자형 결과 코드도 인식하도록 보완했다. XML의 식별자·좌표 문자열은 숫자로 자동 변환하지 않는다. 오류 코드만 분류하며 원천 오류 메시지·인증키는 반환하지 않는다.

공공데이터의 `crsrdId`, 경찰청의 `INT_NO`, T-DATA의 `itstId`를 임의로 동일시하지 않는다. RTI의 보행 필드는 `*PdsgSttsNm`·`*PdsgRmndCs`이며 T-DATA와 철자가 다르다. 단위는 Swagger에 센티초로 설명되지만 실제 감소율·종료 의미를 확인하지 않았다. 시간대 없는 `totDt`도 그대로 보존한다. 진단 응답은 `predictionReady=false`이며 러닝 대기 계산에 연결하지 않는다.

## 아직 필요한 실제 자료

서울 verified 횡단과 `liveMappings`는 현재 확보하지 못했다. 교차로 중심점·이름·차량 방향으로 보행 횡단을 추측하지 않는다. 공개 예측 설정은 꺼져 있다. 서버 키가 있다는 이유로 예측 가능 상태를 켜지 않는다.

활성화에는 해당 횡단의 양끝점·진행 방향·보행 그룹·횡단 길이와 경로 누락 여부 조사, 실제 보행등과 API 필드 대응, 잔여값 단위·종료 의미가 필요하다. 적색에서 다음 녹색까지 예측하려면 검증된 `minimumGreenSec`도 필요하다. 이 값은 임의의 30초나 한 번 관측한 녹색 길이로 채우지 않는다. 입력 필드는 [라우팅 문서](SEOUL_PACE_SIGNAL_ROUTING_KO.md)를 따른다.

계정 소유자가 T-DATA의 위 세 서비스 활용 승인 상태를 확인하고, 404가 지속되면 공식 담당 부서 `02-2133-4954`에 경로의 운영 여부와 승인 범위를 확인해야 한다. 문의나 신청은 자동 발송하지 않았다.

## 검증 범위와 휴대폰 현장 확인

자동 테스트는 모의 패킷으로 동시각 결합·잘못된 ID/패킷·지연·미래 시각·초 단위 혼동·점멸·지나간 횡단·횡단 보행 시간·누적 대기·유효 구간 종료·429 재시도 제한을 확인한다. 실제 신호의 예측 오차를 측정한 결과가 아니다.

휴대폰 [GPS 진단](https://prismatic-lamington-39f015.netlify.app/real/gps-check)에서 야외 정지 2분과 알려진 거리의 이동을 각각 기록하고 JSON을 내보낸다. 실측 기준 거리를 직접 입력하고, 수신 정확도·중단·복귀·누락 샘플을 함께 확인한다. 현재 시험 기준은 정지 누적 10m 이하, 이동 거리 오차 ±5%이며 통과를 대신 기록하지 않았다.

실제 대기 검증은 확인된 횡단에서 보행등 전환 시각과 앱 예상 도착·대기, 사용한 관측 원천 시각을 함께 기록해 수행한다. 횡단 여부는 현장 신호로 판단한다. GPS 실측과 신호 대기 오차 검증이 끝나기 전에는 현장 검증 완료로 보고하지 않는다.

운영 서버 점검은 `npm run verify:release -- https://prismatic-lamington-39f015.netlify.app 20386`으로 실행한다. 신호 공급자가 막혀 있으면 배포 버전 검사와 라이브 데이터 검사가 별도로 실패·성공을 기록한다. `fieldGpsValidated`와 `futureWaitValidated`는 실제 검증 전까지 `false`다.
