# 서울 실시간 대기 구현 기록 — 2026-10-17

릴리스 ID: `seoul-live-wait-20261017`.

## 구현 결과

러너의 남은 거리와 최신 GPS 페이스로 횡단 도착 시각을 구하고, 앞 횡단의 대기·보행 시간을 다음 도착에 누적한다. 기존 고정 계획 확인 외에, 실시간 보행 상태와 잔여값으로 한 번의 녹색 구간을 계산하는 경로를 추가했다. 단기 계산에는 전체 주기나 epoch를 만들 필요가 없다.

현재 녹색은 잔여시간 안에 보행 횡단과 여유 시간을 마칠 수 있는 도착에만 대기 0초를 준다. 현재 적색은 해당 잔여값이 다음 보행 녹색까지임을 검증하고, 그 녹색의 최소 지속시간을 확인해야 대기를 계산한다. 점멸·불명·결측·초과 범위는 `null`이다. 앞 횡단의 예측이 알려져도 이후 횡단이 미확인이면 경로 총대기는 `null`로 남긴다.

원천 관측은 최대 10초, 한 번의 예측 구간은 최대 300초다. 원천 시각에서 잔여값을 계산하므로 HTTP 수신 지연만큼 카운트다운을 다시 늘리지 않는다. 화면을 그대로 두어도 관측 만료 시 대기 합계를 지운다. 새 주기로 임의 반복하지 않는다. 기본 1초 불확실성 여유, 1.2m/s 보행 속도, 3초 횡단 여유는 시험 가정이며 현장 검증 결과가 아니다.

실행 중 응답 후 5초에 갱신한다. 최신 페이스·진행 거리를 사용하며 TMAP 경로를 매번 다시 받지 않는다. 일시정지·숨김 화면에서 폴링을 중단한다. API가 준 재시도 시각을 화면 복귀 후에도 지킨다. 429 후에는 최소 60초 또는 더 긴 `Retry-After`만큼 조회하지 않는다. 같은 서버 프로세스에서 동시 호출·짧은 반복 조회를 공유한다. 이 상태는 여러 서버 인스턴스 사이의 전역 할당량 제어는 아니다.

## 아직 필요한 실제 자료

서울 verified 횡단과 `liveMappings`는 현재 확보하지 못했다. 교차로 중심점·이름·차량 방향으로 보행 횡단을 추측하지 않는다. 공개 예측 설정은 꺼져 있다. 서버 키가 있다는 이유로 예측 가능 상태를 켜지 않는다.

활성화에는 해당 횡단의 양끝점·진행 방향·보행 그룹·횡단 길이와 경로 누락 여부 조사, 실제 보행등과 API 필드 대응, 잔여값 단위·종료 의미가 필요하다. 적색에서 다음 녹색까지 예측하려면 검증된 `minimumGreenSec`도 필요하다. 이 값은 임의의 30초나 한 번 관측한 녹색 길이로 채우지 않는다. 입력 필드는 [라우팅 문서](SEOUL_PACE_SIGNAL_ROUTING_KO.md)를 따른다.

계정 소유자가 T-DATA의 위 세 서비스 활용 승인 상태를 확인하고, 404가 지속되면 공식 담당 부서 `02-2133-4954`에 경로의 운영 여부와 승인 범위를 확인해야 한다. 문의나 신청은 자동 발송하지 않았다.

## 검증 범위와 휴대폰 현장 확인

자동 테스트는 모의 패킷으로 동시각 결합·잘못된 ID/패킷·지연·미래 시각·초 단위 혼동·점멸·지나간 횡단·횡단 보행 시간·누적 대기·유효 구간 종료·429 재시도 제한을 확인한다. 실제 신호의 예측 오차를 측정한 결과가 아니다.

휴대폰 [GPS 진단](https://prismatic-lamington-39f015.netlify.app/real/gps-check)에서 야외 정지 2분과 알려진 거리의 이동을 각각 기록하고 JSON을 내보낸다. 실측 기준 거리를 직접 입력하고, 수신 정확도·중단·복귀·누락 샘플을 함께 확인한다. 현재 시험 기준은 정지 누적 10m 이하, 이동 거리 오차 ±5%이며 통과를 대신 기록하지 않았다.

실제 대기 검증은 확인된 횡단에서 보행등 전환 시각과 앱 예상 도착·대기, 사용한 관측 원천 시각을 함께 기록해 수행한다. 횡단 여부는 현장 신호로 판단한다. GPS 실측과 신호 대기 오차 검증이 끝나기 전에는 현장 검증 완료로 보고하지 않는다.

운영 서버 점검은 `npm run verify:release -- https://prismatic-lamington-39f015.netlify.app 20386`으로 실행한다. 신호 공급자가 막혀 있으면 배포 버전 검사와 라이브 데이터 검사가 별도로 실패·성공을 기록한다. `fieldGpsValidated`와 `futureWaitValidated`는 실제 검증 전까지 `false`다.
