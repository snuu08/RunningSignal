1. 횡단보도 관리번호별 양끝 좌표 또는 선 geometry(GeoJSON, SHP, GPKG, CSV+WKT 등), 좌표계의 EPSG 또는 정의·단위, 작성 기준일·수정일·유효기간.

## V2X 담당 부서 요청서

대상 연락처: `02-2133-4959` — V2X 신호자료 담당 부서. 아래 내용은 발송 전 요청서다.

제목: 횡단보도 관리번호와 V2X 보행 신호그룹·API 방향 필드의 공식 대응표 요청

경로가 지나는 횡단보도의 신호만 선택하기 위해 다음 대응표와 코드 정의를 요청드립니다.

## UTIC 계정 소유자가 해야 하는 부분과 수령 검사

현재 작업 환경에는 UTIC 인증키가 없고 IP 등록을 대신 진행할 수 없다. 실제 요청을 보낼 PC 또는 백엔드 서버의 공인 egress IP를 UTIC 신청 화면에 등록해야 한다. 이번 작업에서 UTIC 서울 파일을 수령했다고 주장하지 않는다. 응답 코드 `32`는 미등록 IP 오류이며 서울 계획의 존재 여부와 별개다.

등록 후 받은 원본은 `data/signals/inbox/`에 둔다. 인증키가 포함된 URL·화면·응답은 공유 자료에서 제거한다. 파일과 조회 응답은 아래 항목을 각각 확인한다.

| 검사 항목 | 수령할 근거 | 미확인일 때 |
|---|---|---|
| 서울 제공 여부 | 실제 서울 지역 레코드와 제공 범위 | 서울 계획 미확인 |
| 자료 기준일 | 버전·기준일·수집일·적용 기간을 구분한 설명 | 현재 적용 계획 미확인 |
| 대상 교차로 | 국기원입구 및 연등의 `REGION_CD`·`INT_NO`·명칭·위치와 공식 외부 ID 대응 | `2207`/`22207`과 자동 연결하지 않음 |
| 시간대별 계획 | 평일·요일·공휴일·예약 운영, 시간대, 계획 번호, 주기와 단위 | 도착 시각의 계획 미확인 |
| 보행 녹색 | 해당 보행 그룹의 진입 가능 구간·점멸/소거 및 단계 의미 | 보행 구간 미확인 |
| 주기 위상 | 옵셋 기준점·부호·시간 기준·동기화, 주기 경계의 절대 시각 근거 | `epochMs`를 만들지 않음 |
| 현재 적용 | 예외·수동·감응 운영 여부, 실제 적용 계획의 확인 시각 | 오래된 계획을 반복하지 않음 |

`COLLCT_DTIME`이나 다운로드 시각을 `currentPlanConfirmedAt` 또는 `epochMs`로 쓰지 않는다. 현재 신호 관측은 해당 계획이 계속 적용되는지 확인하는 데 사용한다. 서울 계획을 받을 수 없다면 별도 현장 관측의 기간·표본·예측 오차·유효시간을 검증해야 하며, 현재 불을 반복한 결과는 예측 자료가 아니다.

## 받은 자료의 연결과 인수 기준

공급기관별 ID는 원본 namespace와 함께 보존한다. 공식 대응표가 오기 전에는 위치·이름·선의 방향으로 T-DATA와 UTIC를 합치지 않는다. 현재 엔진은 crossing과 plan의 `source`, `sourceIntersectionId`, `pedestrianSignalGroupId`가 모두 맞아야 연결한다. 대응표 수령 후에는 근거를 기록한 정규화 절차에서 같은 내부 ID로 연결해야 한다. 원본 `utic:INT_NO`와 `tdata:itstId`를 곧바로 같은 번호로 취급하지 않는다.

geometry를 받은 뒤에는 횡단선 양끝/선의 CRS를 확인하고 보행 네트워크 링크와 대조한다. 경로상의 진입점까지의 거리를 다시 구해 ETA를 계산한다. 기존 약 89초는 교차로 중심점까지의 추정치로, geometry 도착 전 검증된 횡단 도착 시각이 아니다. 그 뒤 이미 구현된 앞 횡단의 대기 누적을 적용하고 각 횡단 도착 시각에 유효한 계획을 선택한다.

원본 → 정규화 → verified의 기존 ETL·검증을 이용한다. 실제 경로의 횡단 누락 여부, 단계·역방향, 시간대 전환, 현재 적용 확인, 현장 예측 오차를 확인한 뒤 해당 범위만 활성화 후보로 삼는다. 시설 점 후보나 이번 catalog 파일은 verified bundle에 넣지 않는다. 자료가 없는 구간과 총대기는 미확인(`null`)이며, 자료를 모두 확인한 경로에서 계산 결과 대기가 없는 경우에만 `0초`다.
