# 서울 신호·GPS 배포 준비 (2026-10-15)

## 변경

- 미배포 상태였던 최신 T-DATA 결합 현시 API(data_id=10381)와 서울 GPS 거리 보정·페이스 경로 평가를 하나의 브랜치에 복구했다.
- `/api/signals/seoul?service=current&itstId=20386`은 소문자 `apikey`로 공식 결합 현시 API를 호출한다. 인증 오류를 HTTP 200으로 받는 경우도 실패로 구분하며, 제공기관에서 인증키를 응답에 되돌려 보내더라도 제거한다.
- `/api/status`의 `release.id`는 `seoul-gps-20261015`다. 키 설정 여부만으로 실제 신호 수신 성공을 선언하지 않는다.
- 모바일 화면 복귀 시 GPS 구독을 새로 시작한다. 화면 이탈·pagehide 시 즉시 백업하고, 긴 수신 공백을 거리로 연결하지 않는다. 일시정지 후 첫 위치는 새 구간으로 처리한다.
- 설정 > 개발 연결 확인 > 야외 GPS 검사(`/real/gps-check`)에서 실제 기록 엔진을 사용해 제자리 2분 또는 기준 거리 달리기를 측정할 수 있다. 반영·제외한 원본 위치, 정확도, 오류, 화면 이탈, 일시정지, 거리와 페이스를 기기에 저장하고 JSON으로 내보낸다. 일반 운동 기록이나 계정 동기화로 보내지 않는다.
- 검사 비교 기준(제자리 10m, 달리기 ±5%)은 잠정값이다. 종료 전·샘플 부족·수신 공백·로그 한도 초과를 합격으로 표시하지 않는다. 원본 위치를 포함하므로 JSON 공유는 사용자가 결정한다.

## 배포 확인

```bash
npm run test
npm run build
npm run lint
npm run verify:release -- https://snuu08-runningsignal.netlify.app 20386
```

`verify:release`는 배포 버전, 최신 서비스 지원, 실제 데이터 응답, 보행 상태·잔여값 존재와 원천 시각 10초 이내를 각각 확인한다. 모의 GPS나 신호 fixture로 라이브 성공을 주장하지 않는다.

## 현재 확인된 제한

2026-10-15 기존 운영 주소의 `/api/status`는 신호 키 설정 상태를 반환했다. 최신 `current` 서비스 호출은 아직 HTTP 400(지원하지 않는 신호 서비스)으로, 수정 버전이 배포되지 않았다.

Netlify 플러그인의 연결 3개는 모두 동일한 계정이었다. 사용자 프로필의 `site_count`와 전체 사이트 목록은 각각 0과 빈 목록이었다. 기존 `snuu08-runningsignal` 사이트는 이 계정에서 조회되지 않는다. 기존 사이트를 소유한 계정/팀에 대한 연결이 필요하다. 이 플러그인에 공개된 작업은 사이트·배포 조회와 환경변수 관리 등이며, 파일 업로드 또는 배포 생성 작업은 현재 공개되지 않았다. 빈 사이트를 만드는 것으로 실제 배포를 대신하지 않았다.

실제 서울 야외 측정은 아직 하지 않았다. 휴대폰에서 제자리 검사, 알려진 1km 이동, 일시정지·재개, 화면 잠금·복귀를 수행하고 내보낸 원본으로 거리·페이스·공백을 확인해야 한다. 실제 횡단 방향·보행 그룹·운영계획·기준시각과 잔여값 단위가 확인되기 전에는 미래 신호 대기를 숫자로 제공하지 않는다.
