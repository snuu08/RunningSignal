# 신호 API 접근·진단 보완 — 2026-10-17

이 변경은 이전 운영 릴리스 r4를 기준으로 서비스별 인증키 선택과 실패 진단만 보완한다.
RTI를 경로 계산에 연결하거나 서울 예측을 활성화하지 않는다.

## 서비스별 키

기존 SEOUL_TDATA_API_KEY는 공통 기본값이다. .env.example의 서비스별 변수가 있으면 해당 서비스만 덮어쓴다.
신규 통합 API와 현재 전용 현시/잔여 API가 각각 다른 키를 발급하는 경우를 지원한다.
실제 승인 상태나 키의 유효성을 설정 여부만으로 판단하지 않는다.
서버 /api/status의 seoulServicesConfigured는 설정 여부만 나타내며 비밀값을 반환하지 않는다.
통합 키 없이 현재 전용 현시·잔여 키만 있는 경우에도 동일 패킷 결합을 지원한다.
범위 불명 호출 제한은 같은 키를 공유하는 서비스에만 전파한다.

## 진단

T-DATA 실패 응답은 서비스명, 원천 HTTP 상태, 오류 분류, 경과시간을 반환한다.
시간 초과·취소·네트워크/리다이렉트 오류를 분리하고, 임의 예외 이름·본문·키를 노출하지 않는다.
경찰청은 공식 기본 형식인 XML로 요청한다. JSON/XML 모두 기존 파서로 해석하며, 미확인 응답의 최상위 자료형·배열 길이만 기록한다.
형식만 바뀐 응답이나 HTTP 200을 신호 수신 성공으로 간주하지 않는다.

## 검증과 아직 남은 일

GitHub Actions에서 테스트와 TypeScript/Vite 빌드를 실행하도록 추가했다. 실제 실행 결과는 PR 체크에서 확인한다.
이번 변경 시점에는 개발 실행 환경과 클라우드 브라우저 제어가 연결 해제 상태다.
로그인된 T-DATA 계정의 10379·10380·10381 승인 상태, 실제 발급 키, 수정 후 원천 응답은 확인하지 못했다.
이 문서는 자동 테스트를 실제 신호 수신 또는 현장 검증으로 간주하지 않는다.

재호출 제한은 여전히 한 서버 인스턴스의 메모리에 저장된다.
서로 다른 Netlify 인스턴스 사이에서 원자적으로 호출을 조정하려면 영속 저장소와 권한·마이그레이션 검증이 필요하며,
현재 환경에서는 이를 설정·검증할 수 없어 전역 제한이 구현됐다고 주장하지 않는다.
경찰청 응답의 실제 구조가 확인되기 전에는 파서 호환 문제가 해결됐다고 주장하지 않는다.
