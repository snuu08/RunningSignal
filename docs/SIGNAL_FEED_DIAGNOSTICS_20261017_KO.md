# 신호 API 접근·진단 보완 — 2026-10-17

이 변경은 기존 r4 구현을 기준으로 서비스별 인증키 선택과 실패 진단을 보완한다.
횡단 매핑·RTI 경로 연결이나 예측 활성화는 이 변경의 범위가 아니다.

## 서비스별 키

기존 SEOUL_TDATA_API_KEY는 공통 기본값이다. .env.example의 서비스별 변수가 있으면 해당 서비스만 덮어쓴다.
별도로 발급된 데이터셋 키가 있는 경우를 지원하며, 필요한 경우에만 설정한다.
실제 승인 상태나 키의 유효성을 설정 여부만으로 판단하지 않는다.
서버 /api/status의 seoulServicesConfigured는 설정 여부만 나타내며 비밀값을 반환하지 않는다.
통합 키 없이 현재 전용 현시·잔여 키만 있는 경우에도 동일 패킷 결합을 지원한다.
서로 다른 데이터셋 키도 같은 제공기관 계정에 속할 수 있다.
범위 불명 호출 제한은 전체 서비스에 보수적으로 적용하며, 제공기관이 특정 API를 명시한 경우에만 그 서비스로 범위를 한정한다.

## 진단

T-DATA 실패 응답은 서비스명, 원천 HTTP 상태, 오류 분류, 경과시간을 반환한다.
시간 초과·취소·네트워크/리다이렉트 오류를 분리하고, 임의 예외 이름·본문·키를 노출하지 않는다.
경찰청은 공식 기본 형식인 XML로 요청한다. JSON/XML 모두 기존 파서로 해석하며, 미확인 응답의 최상위 자료형·배열 길이만 기록한다.
형식만 바뀐 응답이나 HTTP 200을 신호 수신 성공으로 간주하지 않는다.

## 자동 검증과 남은 구현

코드 커밋 `8c4610e0ce4251dce58454482cdd588ad090440b`에서 GitHub Actions가
32개 파일의 테스트 396개와 TypeScript/Vite 빌드를 통과했다.
회귀 검증에는 키 선택, 현재 전용 쌍 조회, 보수적인 호출 제한 범위,
비밀값 제거, 전송 오류, 미확인 배열 응답이 포함된다.
이 문서는 코드 변경과 자동 테스트 범위를 기록하며 실제 현장 검증을 대신하지 않는다.

재호출 제한은 여전히 한 서버 인스턴스의 메모리에 저장된다.
서로 다른 인스턴스 사이에서 원자적으로 호출을 조정하는 전역 제한은 미구현이다.
공유 저장소와 원자적 갱신 방식, 권한·마이그레이션 및 다중 인스턴스 검증이 추가로 필요하다.
경찰청 파서의 자동 테스트도 실제 제공기관 응답 복구를 증명하지 않는다.

PR에는 대상 릴리스 브랜치 이후의 r4 변경도 포함되므로 전체 변경량이 이번 진단 보완만의 크기는 아니다.
